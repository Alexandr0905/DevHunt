# ВВЕДЕНИЕ

В современных условиях динамичного развития индустрии информационных технологий (IT) рынок труда характеризуется высокой степенью фрагментации. Компании-работодатели размещают вакансии на множестве независимых платформ (HeadHunter, Хабр Карьера, Geekjob, специализированные Telegram-каналы и веб-ресурсы), что существенно усложняет процесс поиска работы для соискателей. Специалистам приходится тратить значительное количество времени на мониторинг десятков ресурсов, ручную фильтрацию дублирующихся предложений и отсеивание нерелевантных позиций из-за отсутствия единых стандартов агрегации и тегирования данных.

Существующие крупные агрегаторы общего профиля часто не учитывают специфику IT-сферы, такую как градация по грейдам (Intern, Junior, Middle, Senior, Lead) и жесткая привязка к стеку технологий. Дополнительно возникает проблема задержки пуш-уведомлений о появлении новых вакансий, что критично для соискателей в условиях высокой конкуренции. Таким образом, разработка специализированной автоматизированной системы, способной в режиме реального времени агрегировать, классифицировать IT-вакансии и мгновенно доставлять их целевой аудитории, является актуальной научно-технической и практической задачей.

В связи с этим была сформулирована цель курсового проекта:

Разработать микросервисную веб-платформу по агрегации IT-вакансий для автоматического сбора, централизованного хранения, фильтрации вакансий по технологическим стекам и грейдам, а также мгновенного пуш-уведомления пользователей через синхронизированного Telegram-бота.

Для достижения поставленной цели необходимо решить следующие задачи:

- Изучить предметную область, провести сравнительный анализ существующих площадок по поиску работы и определить ключевые сценарии использования (Use Case) платформы соискателями и администраторами.
- Спроектировать архитектуру распределенной системы, включая схему реляционной базы данных, структуру REST API эндпоинтов и модель асинхронного взаимодействия с API мессенджера Telegram.
- Разработать модули скрапинга данных (скраперы) на основе современных инструментов автоматизации браузера (Playwright) для обхода ограничений динамических веб-страниц.
- Реализовать бэкенд-компонент системы на базе фреймворка Spring Boot, обеспечив отказоустойчивость, транзакционность на уровне работы с СУБД PostgreSQL и интеграцию с механизмами Spring Security для безопасной авторизации.
- Создать интерактивный пользовательский веб-интерфейс (фронтенд) на базе React и TailwindCSS, включающий в себя канбан-доску для трекинга откликов и панель управления подписками.
- Настроить и реализовать Telegram-бота на основе Long Polling соединения для адресной доставки вакансий в соответствии с пользовательскими фильтрами («чипсами»).
- Провести комплексное тестирование разработанного прототипа, включая симуляцию высоконагруженных триггеров пуш-уведомлений, и проверить корректность работы автоматических шедулеров парсинга.

# 1. Функциональное назначение программного средства

## 1.1 Классы решаемых задач

Разрабатываемая веб-платформа представляет собой комплексное программное решение, предназначенное для автоматизации процессов сбора, агрегации и интеллектуальной фильтрации информации о вакансиях в сфере информационных технологий. Назначение системы заключается в централизации разрозненных данных и предоставлении соискателям единой точки доступа к актуальным предложениям рынка труда с возможностью мгновенного адресного информирования.

В соответствии с бизнес-целями архитектура программного средства спроектирована для решения следующих ключевых классов задач:

### 1. Задачи поиска и интеллектуальной агрегации (Data Mining & Processing)

- **Автоматизированный сбор данных (Скрапинг):** Извлечение неструктурированной информации о вакансиях с разнородных внешних веб-ресурсов (HeadHunter, Хабр Карьера, Geekjob, ТрудВсем) в автоматическом режиме с использованием безголовых браузеров (Headless Browsers) на базе инструментов Playwright [12].
- **Инкрементальный парсинг:** Выявление новых уникальных предложений работодателей в режиме реального времени на основе сопоставления URL-адресов вакансий с записями в существующей базе данных PostgreSQL, что предотвращает дублирование информации [16].
- **Полнотекстовый и атрибутивный поиск:** Предоставление пользователю механизмов гибкой фильтрации агрегированной базы данных по ключевым технологическим стекам (тегам) и квалификационным уровням (грейдам).

### 2. Задачи анализа, проверки и валидации (Data Validation & Analytics)

- **Нормализация данных:** Приведение разнородных структур данных, полученных из различных источников, к единой унифицированной объектной модели (Entity) внутри системы [17].
- **Автоматическое тегирование (Валидация стека):** Лексический анализ заголовков и описаний вакансий для точной классификации и привязки к конкретным ключевым словам (Search Keywords), что исключает появление нерелевантного контента в выдаче.
- **Конвертация и стандартизация метрик:** Валидация финансовых параметров вакансий (заработной платы), перевод различных валют к единому эквиваленту с использованием динамически обновляемых курсов валют через внешние API.
- **Контроль актуальности данных:** Автоматический мониторинг жизненного цикла вакансий. Архитектурный механизм шедулера (VacancyScheduler) осуществляет валидацию статуса вакансий и переводит неактуальные или удаленные на первоисточниках предложения в статус архивных (`activeStatus = false`).

### 3. Задачи оптимизации трудозатрат при решении задач поиска и анализа (Automation & UX Optimization)

- **Сокращение времени мониторинга:** Минимизация временных затрат соискателя на ежедневный ручной обход множества сайтов по трудоустройству за счет консолидации всего ИТ-рынка вакансий в одном интерфейсе.
- **Асинхронное пуш-информирование:** Устранение необходимости постоянного обновления веб-страниц пользователем. Интеграция с Telegram Bot API позволяет мгновенно доставлять целевые уведомления в мессенджер конкретного пользователя в секунду сохранения новой вакансии в БД.
- **Визуализация воронки откликов (Канбан-процесс):** Оптимизация операционной деятельности соискателя по управлению собственными процессами трудоустройства. Интерактивная Канбан-доска позволяет наглядно анализировать этапы взаимодействия с работодателями (Отклик, Интервью, Оффер, Отказ).
- **Управление подписками «в один клик»:** Использование интерактивных элементов интерфейса («чипсов») на фронтенде (React) для мгновенного изменения конфигурации фильтров, данные о которых синхронизируются с базой данных и ТГ-ботом на лету без перезагрузки системы.

## 1.2 Функциональное назначение

Программа предназначена для решения задач автоматизации подбора IT-вакансий, консолидации предложений с различных рекрутинговых платформ в едином информационном пространстве, а также минимизации временных затрат соискателей на поиск работы за счет интеллектуальной фильтрации стека и организации сквозного процесса трекинга откликов.

В соответствии с назначением системы, авторизованный пользователь имеет возможность:

- осуществить гибкую настройку персонального профиля квалификации, используя интерактивные фильтры технологий (Search Keywords) и уровней квалификации (Grades);
- запустить процесс подбора релевантных предложений из агрегированной базы данных как через веб-интерфейс, так и путем отправки команд в синхронизированный Telegram-бот;
- проанализировать текущее состояние рынка труда на основе актуальных финансовых метрик (заработных плат), приведенных к единому рублевому эквиваленту;
- получить результаты анализа и обработки данных в виде персонализированной выборки вакансий, полностью соответствующих заданному технологическому стеку, исключая дубликаты и архивные позиции;
- построить визуальную воронку процесса собственного трудоустройства с помощью интерактивной Канбан-доски, распределяя вакансии по этапам взаимодействия с работодателями (Отклик, Интервью, Оффер, Отказ);
- управлять статусом активности пуш-уведомлений, мгновенно приостанавливая или возобновляя отправку новых вакансий в Telegram-бот «в один клик».

## 1.3 Нефункциональные требования, ограничения и интерфейсы

Разрабатываемое программное средство должно удовлетворять следующим группам нефункциональных требований:

**Требования к производительности (Performance Requirements):**

- **Время отклика системы:** Среднее время отклика веб-интерфейса при получении списка вакансий с фильтрацией не должно превышать 300 мс в условиях локальной работы и 1.5 секунд при сетевом доступе с пропускной способностью канала от 10 Мбит/с.
- **Масштабируемость парсинга:** Система сбора данных должна поддерживать параллельный или последовательный запуск нескольких модулей скрапинга (HhRuScraper, GeekjobScraper, HabrCareerScraper, TrudVsemScraper) без деградации производительности основного бэкенда.
- **Кэширование курсов валют:** Для оптимизации вычислений и снижения количества запросов к внешним API курсы валют должны обновляться асинхронно один раз в 12 часов с помощью планировщика `@Scheduled(fixedRate = 43200000)` и кэшироваться в потокобезопасной коллекции `ConcurrentHashMap` класса `CurrencyService`.

**Требования к надежности и отказоустойчивости (Reliability & Fault Tolerance):**

- **Транзакционная целостность:** Операции записи и обновления данных в реляционной СУБД PostgreSQL должны выполняться в транзакционном контексте (`@Transactional`). При возникновении ошибок на любом из этапов скрапинга или сохранения транзакция должна полностью откатываться.
- **Graceful Degradation (Отказоустойчивость внешних вызовов):** В случае сбоя внешнего API валютных курсов (open.er-api.com), класс `CurrencyService` должен автоматически переходить на предопределенные резервные (fallback) значения курсов (USD/RUB = 90.0, USD/KZT = 450.0, USD/EUR = 0.92). Сбои в работе отдельных скраперов не должны приводить к остановке всей системы — ошибки должны обрабатываться локально на уровне `VacancyScheduler`, логироваться и изолироваться.
- **Изоляция транзакций в Telegram Long Polling:** Бот должен обрабатывать входящие сообщения в ручном транзакционном контексте через `TransactionTemplate` для исключения ошибок доступа к ленивым связям (`LazyInitializationException`) при проверке подписок пользователя.

**Требования к безопасности (Security Requirements):**

- **Аутентификация и авторизация:** Разграничение прав доступа должно осуществляться с помощью протокола JWT (JSON Web Tokens). Бэкенд должен функционировать в режиме Stateless (без сохранения состояния сессии на сервере) [7].
- **Шифрование паролей:** Хранение паролей в базе данных в открытом виде недопустимо. Шифрование паролей должно выполняться с помощью хэш-функции bcrypt (`BCryptPasswordEncoder`) с солью.
- **Ролевая модель:** Доступ к методам администрирования (ручной запуск парсеров, просмотр системных логов) должен быть ограничен ролью `ROLE_ADMIN`. Обычные пользователи обладают ролью `ROLE_USER`.

**Ограничения:**

- **Ограничения парсинга:** Скраперы на базе headless-браузера Playwright должны имитировать поведение реального пользователя (заголовки User-Agent, задержки ввода, обход динамического рендеринга JS), чтобы минимизировать вероятность блокировки по IP-адресу.
- **Лимиты Telegram API:** Бот работает по схеме Long Polling. Объем отправляемых текстовых сообщений ограничен лимитами Telegram Bot API (не более 30 сообщений в секунду суммарно и не более 1 сообщения в секунду в один чат во избежание ошибки HTTP 429 Too Many Requests).
- **Локализация финансовых показателей:** Все финансовые значения вакансий (заработная плата) при анализе должны быть приведены к единой валюте — российскому рублю (RUB) с использованием доллара США (USD) в качестве промежуточной базовой валюты хранения.

**Интерфейсы программного средства [2]:**

- **Внутренний REST API:** Обеспечивает асинхронный обмен данными в формате JSON между React-фронтендом и Spring Boot бэкендом. Защищен JWT-токеном в заголовке `Authorization: Bearer <token>`.
- **Интерфейс Telegram Bot API:** Взаимодействие с серверами Telegram для получения обновлений через Long Polling (`onUpdateReceived`) и отправки push-уведомлений пользователям (`execute(SendMessage)`).
- **Интерфейсы внешних рекрутинговых систем:** Скрапинг веб-интерфейсов HeadHunter, Хабр Карьера, Geekjob с использованием селекторов Playwright DOM. REST-интеграция с API «Работа в России» (ТрудВсем) для получения вакансий по структурированным эндпоинтам.
- **Интерфейс внешнего API курсов валют:** Интеграция с открытым сервисом `https://open.er-api.com/v6/latest/USD` посредством Spring RestClient для получения актуальных курсов валют.

# 2. Проектная часть

## 2.1 Архитектура приложения

Для обеспечения высокой модульности, независимости разработки компонентов, отказоустойчивости и простоты горизонтального масштабирования была выбрана сервис-ориентированная архитектура (SOA) с разделением на фронтенд-клиент (SPA), бэкенд-сервис (REST API) и асинхронный сервис уведомлений (Telegram Bot) [11].

Выбранный архитектурный стиль разделения обязанностей (Separation of Concerns) позволяет:

- **Масштабировать компоненты независимо:** При увеличении количества пользователей фронтенд может раздаваться через CDN, а бэкенд — масштабироваться горизонтально за балансировщиком нагрузки.
- **Использовать асинхронность:** Тяжелые операции парсинга и рассылки уведомлений выполняются в фоновом режиме, не блокируя работу веб-интерфейса и API.
- **Обеспечить гибкость интеграции:** Добавление новых источников вакансий или каналов уведомлений (например, Email или Push в браузере) требует модификации только соответствующих сервисных модулей на бэкенде без изменения клиентской части.

*Рисунок 1 — Архитектурная диаграмма системы*

**Компоненты приложения и распределение функциональности:**

- **React Frontend (Клиентская часть):** Отвечает за рендеринг пользовательского интерфейса, обработку пользовательских событий и валидацию форм. Выполняет HTTP-запросы к REST API бэкенда, хранит JWT-токен авторизации в локальном хранилище браузера (localStorage). Состоит из интерактивной Канбан-доски (KanbanBoard), панели фильтров (FilterPanel), личного кабинета подписок (ProfilePanel) и графиков аналитики (StatsDashboard).
- **Spring Boot Backend (Серверная часть):** Выступает в качестве единой точки входа (API Gateway) для клиента, обрабатывает REST-запросы, выполняет бизнес-логику и управляет транзакциями [4]. Содержит модули безопасности (Spring Security) для проверки JWT-токенов пользователей.
- **Playwright Scraper Engine (Модуль сбора данных):** Фоновый сервис, интегрированный в бэкенд, запускаемый шедулером `VacancyScheduler` по расписанию (раз в час) или по ручному триггеру администратора. Использует Playwright для рендеринга динамических веб-страниц источников вакансий и парсинга контента.
- **Telegram Bot Module (Модуль коммуникации):** Управляет Long Polling сессией с Telegram [10]. Обрабатывает входящие команды привязки аккаунта, предоставляет пользователю настройки подписок напрямую в мессенджере.
- **База данных PostgreSQL (Уровень хранения):** Обеспечивает персистентное хранение данных пользователей, вакансий, откликов (Kanban) и подписок [8].

## 2.3 Модель данных ПС

## 3.1 Диаграмма классов и их описание

Архитектура серверной части веб-платформы DevHunt спроектирована на основе строгого разделения обязанностей по пакетам. Это упрощает изолированное тестирование компонентов [5].

Диаграмма пакетов иллюстрирует структуру модулей бэкенд-приложения и зависимости между ними.

*Рисунок 7 — Диаграмма пакетов*

**Описание пакетов:**

- `com.devhunt.config` — Содержит класс `BotConfig` для инициализации и регистрации Telegram-бота в системе.
- `com.devhunt.security` — Отвечает за аутентификацию и авторизацию. Включает фильтр JWT (`AuthTokenFilter`), утилиты для работы с токенами (`JwtUtils`), класс конфигурации (`SecurityConfig`) и сервис авторизации (`UserDetailsServiceImpl`).
- `com.devhunt.controller` — Содержит REST-контроллеры, которые принимают HTTP-запросы от React-приложения, валидируют их и передают в сервисный слой.
- `com.devhunt.dto` — Содержит легковесные объекты передачи данных (Data Transfer Objects), используемые для обмена данными через REST API.
- `com.devhunt.model` — Описывает доменные JPA-сущности и перечисления (`com.devhunt.model.enums`), которые напрямую отображаются на таблицы реляционной СУБД PostgreSQL.
- `com.devhunt.repository` — Содержит интерфейсы репозиториев (Spring Data JPA) для выполнения CRUD-операций в базе данных, а также спецификацию сложной фильтрации `VacancySpecification`.
- `com.devhunt.service` — Содержит бизнес-логику приложения: планировщик сбора вакансий, расчет статистики и конвертацию валют.
- `com.devhunt.service.scraper` — Содержит интерфейс скрапинга `JobScraper`, фабрику `ScraperFactory` и реализации парсеров для конкретных рекрутинговых ресурсов.
- `com.devhunt.service.telegram` — Реализует логику взаимодействия с Telegram Bot API: обработку команд соискателей и асинхронную рассылку push-уведомлений.
- `com.devhunt.exception` — Содержит глобальный обработчик исключений (`GlobalExceptionHandler`), форматирующий ошибки сервера в понятные клиенту JSON-ответы.

**Диаграмма классов, группа 1 — модели данных и репозитории.** Данная группа классов отвечает за персистентное хранение данных (Persistence Layer) и представляет объектно-реляционное отображение (ORM) базы данных в Java-код.

*Рисунок 8 — Диаграмма классов первой группы*

**Описание классов Группы 1:**

- **Vacancy:** Хранит структурированную информацию о найденной вакансии. Ключевые поля: `url` (уникальная ссылка-первоисточник для исключения дубликатов), `salaryUsd` (приведенная к общему знаменателю зарплата для фильтрации), `activeStatus` (флаг актуальности).
- **User:** Хранит учетные данные пользователя, статус интеграции с Telegram и настройки фильтров для рассылки. Ключевые поля: `email` (логин), `password` (хэш), `telegramChatId` (уникальный ID чата для адресной отправки пушей), `subscribedKeywords` и `subscribedGrades` (коллекции подписок).
- **SearchKeyword:** Представляет собой тег технологии (например, «React», «Java») для классификации вакансий и фильтрации.
- **JobApplication:** Связывает пользователя и вакансию на Канбан-доске откликов. Ключевые поля: `status` (стадия воронки), `createdAt` и `updatedAt` (для отслеживания времени нахождения на этапах).
- **Grade:** Enums-класс, описывающий уровни квалификации: стажер, джуниор, мидл, сеньор, тимлид.
- **ApplicationStatus:** Enums-класс, описывающий 5 колонок Канбан-доски.
- **Интерфейсы репозиториев** (`UserRepository`, `VacancyRepository`, `JobApplicationRepository`, `SearchKeywordRepository`): Наследуют `JpaRepository`, предоставляют автоматическую генерацию SQL-запросов к СУБД PostgreSQL.
- **VacancySpecification:** Строит динамические SQL-запросы на основе Spring Data JPA Criteria API для реализации гибкого поиска вакансий по множеству необязательных параметров.

---

**Диаграмма классов второй группы: сервисы бизнес-логики, парсинг и уведомления.** Данная группа классов реализует ключевой функционал сбора, обработки данных, валютной нормализации и асинхронного взаимодействия с Telegram.

*Рисунок 9 — Диаграмма классов второй группы*

**Описание классов группы 2:**

- **VacancyScheduler:** Координатор процесса скрапинга. По расписанию активирует парсеры, сравнивает результаты с базой данных, выявляет новые уникальные вакансии и запускает цепочку Telegram-уведомлений.
- **CurrencyService:** Асинхронно стягивает курсы валют из внешнего финансового API и выполняет математические конвертации валют (RUB, USD, EUR, KZT) к единому эквиваленту.
- **StatisticsService:** Формирует агрегированные выборки из базы данных для графиков аналитики фронтенда (востребованность навыков, средние зарплаты по направлениям).
- **JobScraper (Интерфейс):** Задает контракт для всех модулей парсинга. Каждый новый парсер обязан реализовать его методы [9].
- **Классы скраперов** (`HhRuScraper`, `GeekjobScraper`, `HabrCareerScraper`, `TrudVsemScraper`): Выполняют сбор вакансий. Скраперы HH, Habr и Geekjob используют движок Playwright для обхода ограничений динамического рендеринга страниц, а `TrudVsemScraper` обращается напрямую к открытому API сервиса «Работа в России».
- **ScraperFactory:** Реализует паттерн «Фабрика», собирая все зарегистрированные бины скраперов в единый список для пакетного запуска в планировщике [13].
- **DevHuntBot:** Наследует `TelegramLongPollingBot`. Обрабатывает входящие сообщения от соискателей, привязывает аккаунты по UUID-токенам и предоставляет возможность запросить свежие вакансии по фильтрам прямо в мессенджере (команда `/latest`).
- **TelegramNotificationService:** Выполняет предиктивную фильтрацию вакансий перед отправкой пуш-уведомления. Сравнивает грейд и технологии новой вакансии с массивом подписок каждого пользователя и при полном совпадении инициирует отправку сообщения.

---

**Диаграмма классов группы 3: контроллеры, безопасность и DTO.** Данная группа классов обеспечивает обработку входящих сетевых HTTP REST-запросов, защиту конечных точек и валидацию передаваемых данных.

*Рисунок 10 — Диаграмма классов третьей группы*

**Описание классов Группы 3:**

- **REST-Контроллеры** (`AuthController`, `VacancyController`, `UserController`, `KanbanController`, `AdminController`): Принимают входящие HTTP запросы, сопоставляют их с URI (Routing), извлекают JWT-токен пользователя из контекста безопасности, делегируют выполнение задач соответствующим сервисам и возвращают клиенту HTTP-ответы (`ResponseEntity`) с JSON-структурами.
- **DTO** (Рекорды Java: `AuthRequest`, `AuthResponse`, `TelegramSettingsDto`, `UserProfileDto`): Иммутабельные структуры данных (Java Records), заменяющие громоздкие классы. Используются для строгой типизации принимаемого и отправляемого JSON-контента на границах системы.
- **SecurityConfig:** Главный конфигуратор Spring Security. Отключает сессии (Stateless режим), настраивает CORS правила для связи с фронтендом (`http://localhost:3000`), регистрирует фильтры безопасности и задает правила публичного/приватного доступа к эндпоинтам.
- **AuthTokenFilter:** Перехватывает каждый входящий HTTP запрос, извлекает JWT-токен из заголовка `Authorization`, валидирует его с помощью `JwtUtils` и в случае успеха помещает данные о пользователе в контекст безопасности `SecurityContextHolder`.
- **JwtUtils:** Сервисный класс для генерации криптографически подписанных JSON Web Tokens, извлечения имени пользователя (email) из токенов и проверки их валидности по времени жизни и сигнатуре.
- **GlobalExceptionHandler:** Централизованный перехватчик системных ошибок бэкенда (`@RestControllerAdvice`). При возникновении непредвиденных исключений на сервере перехватывает их и возвращает клиенту корректный и безопасный JSON-ответ с описанием ошибки вместо сырого стектрейса Java.

- **Личный кабинет управления подписками:** Интерактивная настройка профиля соискателя с использованием визуальных элементов для множественного выбора отслеживаемых технологий (React, Java, QA и др.) и квалификационных грейдов (Junior, Middle, Senior, Lead).
- **Адресная push-рассылка в режиме реального времени:** Интегрирован асинхронный Telegram-бот (`DevHuntBot`). Реализован алгоритм сопоставления грейдов и тегов новой вакансии с подписками соискателей. Оповещения в Telegram доставляются в течение 1.2 секунды после фиксации вакансии в БД.

- **Панель визуальной аналитики:** Интерактивный дашборд (`StatsDashboard`), строящий круговые и столбчатые графики распределения вакансий по ИТ-направлениям, средней заработной платы по грейдам и динамики появления новых вакансий за последние 6 месяцев.

Разработанный прототип веб-платформы DevHunt продемонстрировал высокую надежность, модульную масштабируемость, отказоустойчивость при сетевых сбоях смежных систем и полное соответствие современным требованиям ИТ-индустрии к удобству пользовательского опыта (UX). # ПРИЛОЖЕНИЕ 3

Техническое задание на разработку веб-платформы DevHunt, определяет назначение, структуру, функциональные характеристики и технические требования к создаваемому программному продукту DevHunt.

**Основание для разработки:** Основанием для разработки является задание на выполнение курсового проекта по дисциплине «Проектирование информационных систем» для студентов направления подготовки «Информационные системы и технологии».

**Назначение системы:** Программный комплекс DevHunt предназначен для автоматизированного сбора, агрегации и интеллектуальной фильтрации вакансий в сфере ИТ с ведущих рекрутинговых платформ, ведения интерактивного учета этапов трудоустройства соискателя (Канбан-доска) и автоматического push-информирования соискателей в мессенджере Telegram на основе их индивидуальных подписок.

**Требования к программе:**

*3.1 Требования к функциональным характеристикам*

Программа должна обеспечивать выполнение следующих функций:

- **Сбор вакансий:** Асинхронный парсинг данных с ресурсов HeadHunter, Хабр Карьера и Geekjob с использованием headless-браузера Playwright для обхода динамического рендеринга страниц, а также интеграцию по API с системой «Работа в России» (ТрудВсем).
- **Инкрементальность:** Сохранение только уникальных вакансий на основе URL-адреса с защитой от дублирования.
- **Нормализация окладов:** Приведение всех валют к рублю (RUB) на основе динамического API курсов.
- **Telegram-интеграция:** Привязка аккаунта соискателя к Telegram-боту по уникальному одноразовому UUID-токену и автоматическая рассылка новых релевантных вакансий по совпадению тегов технологий и грейда.
- **Канбан-доска:** Интерактивный Drag-and-Drop интерфейс отслеживания воронки трудоустройства со стадиями: Просмотрено, Откликнулся, Интервью, Оффер, Отказ.
- **Интерфейс администратора:** Ведение словаря ключевых слов поиска и принудительный запуск сессии скрапинга.

*3.2 Требования к надежности*

- **Целостность данных:** Выполнение всех критических транзакций записи в СУБД PostgreSQL в транзакционном контексте (`@Transactional`).
- **Отказоустойчивость:** Сохранение работоспособности системы при сбоях отдельных парсеров или внешних API валют за счет локализации ошибок в планировщике и переключения на fallback-курсы.

*3.3 Требования к условиям эксплуатации*

- Система должна запускаться на серверах под управлением Windows, macOS или Linux.
- База данных PostgreSQL должна разворачиваться локально или в контейнере Docker на порту 5432.
- Серверная часть требует установленной Java версии 21.

*3.4 Требования к аппаратной совместимости*

**Руководство по интеграции и использованию Telegram-бота**

**Генерация ссылки привязки:** Перейдите в свой Профиль на сайте и нажмите кнопку «Привязать Telegram». Система сгенерирует для вас персональную защищенную UUID-ссылку вида `https://t.me/DevHuntBot?start=UUID`.

**Активация бота:** Кликните по ссылке — откроется Telegram-клиент. Нажмите кнопку «Запустить» (`/start`). Бот считает UUID, привяжет ваш аккаунт и отобразит приветственное меню.

**Настройка уведомлений:** Вы можете управлять уведомлениями прямо в личном кабинете на сайте (включать/выключать Telegram-рассылку общим переключателем).

**Команды бота:**
- `/start` — запускает бота и проверяет статус привязки;
- `/profile` — выводит текущие активные подписки соискателя на технологии и грейды;
- `/pause` — приостанавливает рассылку пуш-уведомлений о вакансиях без отвязки бота;
- `/latest` — принудительно высылает в чат 3 свежие случайные вакансии, точно подходящие под ваши подписки.
