# Требования к ПО — Агрегатор вакансий «DevHunt»

Разработка веб-сервиса начинается с процесса формулирования требований, в котором, исходя из потребностей соискателей, результатов исследования рынка job-платформ и личного опыта разработчика, должен быть создан документ, максимально точно определяющий задачи команды. Этот документ — внешнее описание ПС или требования к ПС.

---

# Методы сбора и извлечения требований

## Анализ предметной области

Программное решение реализует модель предметной области. Для агрегатора вакансий предметная область — рынок труда в IT, поведение соискателей и механизмы публикации вакансий на различных платформах.

Анализом предметной области называют деятельность, направленную на:

- выявление реальных потребностей соискателей (вручную обходить 5+ платформ неудобно и неэффективно)
- выяснение смысла высказанных пожеланий пользователей
- выявление свойств желаемых результатов
- определение набора задач для их достижения
- определение набора сущностей, участвующих в решении задач
- определение границ ответственности программной системы

**Источники требований:**

- беседы с соискателями (студенты, джуны, middle-разработчики)
- изучение существующих платформ: hh.ru, LinkedIn, Habr Career, Telegram-каналы с вакансиями
- анализ отчётов об ошибках и запросов к конкурирующим продуктам
- маркетинговые исследования и опросы соискателей
- наблюдение за поведением пользователей при поиске работы
- анализ страниц карьеры крупных IT-компаний (Тинькофф, ВК, Авито, Яндекс и др.)

## Задача 1 — Концепция проекта

### 1. Описание проблемы

| | |
|---|---|
| **Проблема** | Соискатель вынужден вручную мониторить множество независимых платформ (hh.ru, LinkedIn, Habr Career, сайты компаний) для поиска подходящих вакансий |
| **Воздействует на** | Всех IT-специалистов: студентов и джунов, ищущих стажировки и первую работу; middle/senior разработчиков и смежных специалистов (QA, DevOps, аналитиков, дизайнеров) |
| **Результатом чего является** | Потеря времени, пропуск актуальных вакансий, дублирование усилий при поиске, разрозненность данных о вакансиях в разных форматах |
| **Выигрыш от ПП** | Экономия времени, единое пространство поиска, удобная фильтрация, возможность быстрого отклика и отслеживания стажировок |

### 2. Назначение программного средства

| Вопрос | Ответ |
|---|---|
| Кто применяет ПС для решения своих задач? | Все IT-специалисты: студенты и джуны (поиск первой работы/стажировки), middle/senior разработчики (целевой поиск), а также смежные специалисты (QA, DevOps, аналитики, дизайнеры) |
| От каких систем/пользователей поступают входные данные? | API hh.ru, LinkedIn, Habr Career; парсинг карьерных страниц компаний (Тинькофф, ВК, Авито и др.) |
| Кто/что использует результаты? | Соискатели через веб-интерфейс; потенциально — сторонние сервисы через API |
| Какие сторонние системы участвуют в обработке? | OAuth-провайдеры (Google, GitHub), SMTP для уведомлений, планировщик для периодического сбора вакансий |

## Задача 3 — Анализ конкурентов

### Сравнительная характеристика конкурирующих решений

| Проблема | Сегмент рынка | hh.ru | LinkedIn | Habr Career | Приоритет |
|---|---|---|---|---|---|
| Агрегация вакансий из нескольких источников | U, R, XS–M | - | - | - | e |
| Поиск по нескольким фильтрам одновременно | U, R | + | + | + | e |
| Отдельный раздел стажировок IT-компаний | U (студенты) | - | - | - | e |
| Автоотклик на вакансии | R, XS | - | - | - | u |
| Уведомления о новых вакансиях | U, R | + | + | + | u |
| Сохранение избранных вакансий | U, R | + | + | + | u |
| Отслеживание статуса откликов | R, XS | + | + | - | u |
| Просмотр вакансий без регистрации | U | + | - | - | d |
| Сравнение вакансий между собой | R | - | - | - | d |
| Единый профиль для нескольких платформ | R, XS | - | - | - | d |

> **Условные обозначения:** `e` — обязательно (essential), `u` — полезно (useful), `d` — желательно (desirable)

### Вывод по анализу конкурентов

Ни одна из существующих платформ не решает ключевую задачу — **агрегацию вакансий из нескольких источников в одном месте**. Ни hh.ru, ни LinkedIn, ни Habr Career не агрегируют вакансии с конкурирующих площадок. Также отсутствует выделенный раздел стажировок крупных российских IT-компаний (Тинькофф, ВК, Авито, Яндекс и др.). Это создаёт чёткое конкурентное преимущество для нового продукта.

---

### Образ программного продукта

**«для»** — IT-специалистов и студентов, ищущих работу или стажировку;

**«который»** — тратят значительное время на ручной мониторинг множества платформ с вакансиями;

**«этот»** — **DevHunt**;

**«является»** — веб-агрегатором IT-вакансий;

**«который»** — автоматически собирает вакансии с hh.ru, LinkedIn, Habr Career и карьерных страниц компаний и отображает их в едином удобном интерфейсе с фильтрацией и быстрым откликом;

**«в отличие от»** — hh.ru, LinkedIn и Habr Career, каждая из которых показывает только собственные вакансии;

**«наш продукт»** — единственный сервис, объединяющий все источники вакансий, включая отдельный раздел стажировок крупных IT-компаний, с поддержкой автоотклика.

## Задача 5 — Моделирование сценариев использования

### 1. Иерархия заинтересованных лиц

```
Заинтересованные лица
├── Соискатели
│   ├── Студент / стажёр (ищет стажировку или первую работу)
│   ├── Junior-разработчик (опыт до 1 года)
│   ├── Middle/Senior специалист (целевой поиск с фильтрами)
│   └── Смежные IT-специалисты (QA, DevOps, аналитики, дизайнеры)
├── Администратор системы
│   └── Управляет источниками, модерирует контент
└── Внешние системы (не люди)
    ├── API-источники (hh.ru, LinkedIn, Habr Career)
    └── Карьерные страницы компаний (парсинг)
```

### 2. Сценарии использования

#### Актор: Студент / стажёр

**UC-01: Просмотр стажировок**

1. Пользователь открывает вкладку «Стажировки»
2. Система отображает актуальные стажировки крупных IT-компаний
3. Пользователь фильтрует по специальности и городу
4. Пользователь открывает карточку стажировки
5. Пользователь переходит на страницу отклика

*Альтернативный сценарий:* Стажировок по фильтру не найдено → система предлагает расширить критерии или подписаться на уведомления

#### Актор: Соискатель (любой уровень)

**UC-02: Поиск вакансий по фильтрам**

1. Пользователь вводит ключевое слово (например, «Python»)
2. Пользователь задаёт фильтры: город, уровень, зарплата, формат (удалённо/офис)
3. Система возвращает дедуплицированные вакансии из всех источников
4. Пользователь сортирует результаты (по дате, зарплате, релевантности)
5. Пользователь открывает карточку вакансии и переходит к отклику

*Альтернативный сценарий:* Пользователь добавляет вакансию в «Избранное» для отклика позже

**UC-03: Подписка на уведомления**

1. Пользователь сохраняет поисковый запрос с фильтрами
2. Система периодически проверяет новые вакансии по запросу
3. При появлении новых вакансий — отправляет email-уведомление
4. Пользователь переходит по ссылке в письме и видит новые вакансии

#### Актор: Администратор

**UC-04: Управление источниками**

1. Администратор входит в панель управления
2. Добавляет новый источник (URL или API-endpoint)
3. Настраивает расписание парсинга
4. Проверяет статус доступности источника

## Задача 7 — Техническое задание (ключевые разделы)

### Наименование системы
Веб-сервис агрегации IT-вакансий **DevHunt**

### Цель создания
Создание веб-приложения для автоматического сбора, нормализации и отображения IT-вакансий из множества источников в едином интерфейсе

### Требования к функциям системы (Реализованный функционал)

1. **Функция авторизации и регистрации пользователя** — обеспечение безопасного Stateless-доступа соискателей к личному кабинету и Kanban-доске откликов на основе JWT-токенов и BCrypt-хеширования паролей.
2. **Функция выбора вакансий по фильтрам** — динамическая SQL-фильтрация вакансий по уровням квалификации (грейдам) и ИТ-технологиям с мгновенным React-обновлением интерфейса без перезагрузки страниц.
3. **Функция сбора статистики по вакансиям** — агрегация финансовых показателей ИТ-рынка и автоматическая мультивалютная конвертация окладов в рубли (RUB) по актуальным курсам валют через API для аналитического дашборда.
4. **Функция отслеживания статуса откликов** — персональная CRM-система соискателя на базе интерактивной Канбан-доски с поддержкой Drag-and-Drop для контроля этапов воронки трудоустройства.
5. **Функция управления данными и пользователями (Панель администратора)** — защищенный ROLE_ADMIN интерфейс администрирования для наполнения справочников технологий, просмотра системных логов и ручного запуска парсеров.
6. **Функция подписки на уведомления о новых вакансиях** — асинхронный фоновый парсинг, интеллектуальный UUID-матчинг подписок и мгновенная отправка push-сообщений в Telegram-бот при появлении новых вакансий по стеку соискателя.

### Требования к надёжности
- Доступность сервиса: не менее 99% времени в рабочие часы
- Восстановление после сбоя источника: система продолжает работу при недоступности любого отдельного источника

## 💻 Реальный технический стек проекта

| Слой / Компонент | Технологическое решение | Описание |
|---|---|---|
| **Backend Core** | Java 21, Spring Boot 3.2.4 | Основная бизнес-логика, планировщик фоновых задач, транзакции JPA. |
| **Security Layer** | Spring Security, stateless JWT | Защита REST API, авторизация сессий с помощью JSON Web Tokens, хэширование паролей Bcrypt. |

| **Notification Channel** | Telegram Bot API (Long Polling) | Асинхронная доставка push-уведомлений соискателям о появлении вакансий по их фильтрам. |
| **Frontend** | React 18, TypeScript, TailwindCSS | Одностраничное веб-приложение (SPA) с адаптивным UI, Kanban-доской и графиками аналитики. |

## 🚀 Инструкция по локальному запуску

### 1. Подготовка Базы Данных (PostgreSQL)
Убедитесь, что у вас запущена СУБД PostgreSQL. Вы можете запустить её локально.

**Вариант А: Локальный запуск**
Создайте пустую базу данных с именем `devhunt`:
```sql
CREATE DATABASE devhunt;
```
По умолчанию бэкенд ожидает подключение к `localhost:5432` с пользователем `postgres` и паролем `postgres`. Изменить параметры можно в файле `devhunt-backend/src/main/resources/application.properties` или через переменные окружения.

**Вариант Б: Запуск в Docker**
Вы можете поднять СУБД PostgreSQL одной командой:
```bash
docker run --name devhunt-postgres -p 5432:5432 -e POSTGRES_DB=devhunt -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=postgres -d postgres:15
```

### 2. Запуск бэкенда (Spring Boot)
1. Перейдите в каталог бэкенда:
   ```bash
   cd devhunt-backend
   ```
2. Скомпилируйте проект и скачайте зависимости через Maven:
   ```bash
   mvn clean package
   ```
3. Установите headless-браузеры для Playwright (необходимо для работы парсеров):
   ```bash
   mvn exec:java -e -D exec.mainClass=com.microsoft.playwright.CLI -D exec.args="install"
   ```
4. Запустите бэкенд-приложение:
   ```bash
   mvn spring-boot:run
   ```
   Или запустите файл DevHuntApplication.java через вашу IDE.
   
   Сервер запустится по адресу `http://localhost:8080`. База данных автоматически наполнится таблицами. При первом запуске планировщик запустит первичный скрапинг вакансий.

### 3. Запуск фронтенда (React SPA)
1. Откройте новый терминал и перейдите в каталог фронтенда:
   ```bash
   cd devhunt-frontend
   ```
2. Установите зависимости npm:
   ```bash
   npm install
   ```
3. Запустите сервер разработки:
   ```bash
   npm run dev
   ```
   Интерфейс приложения будет доступен по адресу `http://localhost:3000`.

## 🤖 Руководство по интеграции и использованию Telegram-бота

Интеграция с Telegram-ботом является одной из ключевых особенностей платформы **DevHunt**, позволяя соискателям не тратить время на постоянное обновление веб-страниц и моментально узнавать о новых вакансиях, соответствующих их критериям.

### 1. Процесс привязки Telegram-аккаунта (OAuth UUID-токен)
Связывание веб-аккаунта с Telegram-ботом полностью безопасно и основано на генерации временных UUID-токенов:
1. Зарегистрируйтесь и авторизуйтесь на сайте `http://localhost:3000`.
2. Перейдите в личный кабинет (вкладка **Профиль** в мобильной версии или клик по email-адресу в верхнем меню на десктопе).
3. В секции «Интеграция с Telegram» нажмите кнопку **«Привязать Telegram»**.
4. Веб-платформа сгенерирует временный UUID-токен, свяжет его в кэше бэкенда с вашим email и отобразит кликабельную ссылку вида:
   `https://t.me/ИмяВашегоБота?start=3f89e5d2-a7b1-4c92-bd88-66258f1aef2a`
5. Нажмите на ссылку, в открывшемся приложении Telegram нажмите кнопку **«Запустить»** (или отправьте команду `/start <UUID>`).
6. Бот сопоставит полученный UUID-токен с вашим аккаунтом на сервере, запишет `telegram_chat_id` в базу данных и пришлет сообщение:  
   `✅ Аккаунт успешно привязан! Бот активно отслеживает вакансии по вашим фильтрам.`

### 2. Доступные интерактивные команды в боте
Пользователь может управлять подбором вакансий напрямую из мессенджера с помощью следующих команд:
* `/start` — Инициализирует работу бота, выводит приветственное сообщение. При передаче токена привязывает аккаунт к сайту.
* `/profile` — Отображает информацию о текущем профиле: ваш email, статус активности рассылки (Включена/На паузе), а также текущий список отслеживаемых технологий и квалификационных грейдов, выбранных на сайте.
* `/pause` — Переключает режим активности push-уведомлений «в один клик». Позволяет временно отключить рассылку бота без удаления привязки аккаунта, а затем возобновить её в любой момент.
* `/latest` — Возвращает подборку из **3 случайных активных вакансий**, которые полностью соответствуют заданным на сайте фильтрам по технологическому стеку и грейду. Полезна для ручной проверки актуальности рынка труда.

### 3. Механизм фильтрации и отправки Push-уведомлений
Рассылка бота работает по предиктивному асинхронному принципу:
1. Каждые 60 минут планировщик `VacancyScheduler` запускает скрапинг новых вакансий с HH, Хабра и Geekjob.
2. При нахождении **уникальной новой вакансии** (по её URL) система сохраняет её в БД и производит лингвистический анализ заголовка для выявления ИТ-направления и технологий (например, «Java», «React», «QA»).
3. Сервис `TelegramNotificationService` запрашивает всех соискателей с привязанным `telegram_chat_id` и включенным тумблером уведомлений.
4. Для каждого соискателя проверяются подписки:
   * **Технологии**: вакансия отправляется, если пользователь подписан на данную технологию (или если у него не выбрана ни одна технология — тогда присылается весь рынок).
   * **Грейд**: вакансия отправляется, если её грейд совпадает со списком подписок пользователя (или если подписки на грейды пусты).
5. При совпадении критериев бот мгновенно высылает красивую карточку вакансии в Telegram с указанием должности, компании, грейда, нормализованной зарплаты в рублях и прямой ссылкой на первоисточник.

## ⚙️ Управление данными и принудительный запуск парсинга
Система автоматически собирает данные каждый час, но вы можете инициировать скрапинг принудительно:
* **Через веб-интерфейс**: Авторизуйтесь под учетной записью с ролью администратора (`ROLE_ADMIN`), перейдите во вкладку **Админ панель** и нажмите кнопку **«Запустить скрапинг вакансий»**.
* **Через GET-запрос**: Вызовите в браузере или API-клиенте эндпоинт:  
  [👉 Запустить скрапинг сейчас](http://localhost:8080/api/vacancies/scrape-now) (доступен публично для тестирования MVP).

Логи сбора и нормализации вакансий в реальном времени будут выводиться в консоль вашего терминала Spring Boot.
